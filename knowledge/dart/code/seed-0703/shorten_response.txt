1. Manual parsing uses `as` casts and `Enum.values.byName` which throws a raw `ArgumentError` if `status` is not exactly one of "active", "inactive", "unknown" (undocumented exception, Tier B).

2. json_serializable and freezed share JSON decoding logic using `$enumDecode`, throwing a documented and catchable `CheckedFromJsonException` on unknown enum strings.

3. built_value uses `BvStatus.valueOf` which throws an `ArgumentError` on unknown enum strings, similar to manual but wrapped in built_value error handling.

4. For `id`, manual requires `int` exactly (`json['id'] as int`), json_serializable/freezed accept any `num` and convert via `.toInt()`, built_value expects `int` and likely rejects non-int types.

5. For `amount`, all require a `String` exactly; non-string values cause rejection.

6. For `name`, all accept `null` or `String`; manual and json_serializable/freezed use nullable casts, built_value uses nullable field with serializer.

7. For `tags`, manual casts to `List` then maps elements as `String`; json_serializable/freezed cast to `List<dynamic>` then map to `String`; built_value expects `BuiltList<String>` and rejects non-list or lists with non-string elements.

8. For `child`, all accept `null` or nested record; manual and json_serializable/freezed recursively call their own `fromJson`; built_value uses serializer and builder pattern.

9. Missing fields: manual and json_serializable/freezed require all fields present (no defaults); built_value requires all non-nullable fields; nullable `name` and `child` omitted fields decode as null.

10. Key differences:
   - `status` unknown enum strings: manual and built_value throw raw `ArgumentError` (undocumented), json_serializable/freezed throw documented `CheckedFromJsonException`.
   - `id` as non-int number (e.g. float): manual rejects, json_serializable/freezed accept and convert, built_value likely rejects.
   - `tags` with non-string elements: manual and json_serializable/freezed reject on cast, built_value rejects during builder build with nested field error.
   - `name` or `child` wrong types or missing: differences in nullability and error types.
   - Extra fields ignored by all.

11. built_value throws nested field errors on collection or nested object build failures, differing from manual’s raw cast errors and json_serializable/freezed’s checked exceptions.

12. Overall, enum decoding and numeric type coercion on `id` are main divergence points; manual and built_value are less forgiving or less documented in error reporting than json_serializable/freezed.
