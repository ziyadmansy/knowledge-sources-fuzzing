1. Gson accepts missing required fields, decoding missing integers as 0, missing strings as null, and missing enums as null; Moshi and kotlinx.serialization reject missing required fields; Jackson rejects missing non-nullable fields but accepts missing nullable ones.  
2. Gson accepts null for non-nullable fields (id, amount, status, tags), decoding null integers as 0 and null strings as null; Moshi and kotlinx.serialization reject null for non-nullable fields; Jackson rejects null for non-nullable fields.  
3. Gson and Moshi accept wrong JSON types for string fields if convertible (e.g., number for amount), decoding numbers as strings; kotlinx.serialization rejects wrong types; Jackson accepts convertible types for strings but rejects invalid enum values.  
4. Gson and Jackson accept missing enum fields, decoding them as null; Moshi and kotlinx.serialization reject missing enums; Gson accepts unknown enum values by decoding as null; Moshi, kotlinx.serialization, and Jackson reject unknown or case-variant enum values.  
5. Gson and Moshi accept missing or null nested objects; kotlinx.serialization rejects missing nested objects; Jackson accepts missing nested objects but rejects null nested objects if non-nullable.  
6. Gson accepts extra unknown keys and duplicate keys silently; Moshi accepts extra unknown keys but rejects duplicates (not tested explicitly); kotlinx.serialization rejects extra unknown keys; Jackson rejects extra unknown keys.
