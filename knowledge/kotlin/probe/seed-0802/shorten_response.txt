1. All four accept fully well-formed documents with correct types (Probe 1).

2. All accept integer `id` as either JSON number or string containing a number (Probes 1,2,9).

3. Gson, Moshi, and Jackson accept `amount` as string or number, converting number to string; kotlinx rejects number (Probes 1,3,13).

4. Gson and Moshi accept `name` as string or number (converted to string); kotlinx rejects number; Jackson accepts number converted to string (Probes 1,4).

5. `status` must be "active", "inactive", "unknown" or null; Gson accepts unknown string as null; Moshi, kotlinx, Jackson reject unknown string (Probe 5).

6. `tags` must be an array; all reject non-array (Probe 6).

7. Gson, Moshi, Jackson accept non-string elements in `tags` by converting to string or allowing null; kotlinx rejects non-string or null elements (Probes 7,14,15).

8. All accept `child` as null or valid nested record; nested `id` can be string or number (Probes 8,9).

9. Gson tolerates empty object `{}` as `child`, filling missing fields with defaults or nulls; others reject missing required fields or nulls where not allowed (Probe 12).

10. Gson and Moshi accept unknown extra fields at top level and nested; kotlinx and Jackson reject unknown fields (Probes 10,18).

11. Gson accepts null for `status` and decodes as null; Moshi, kotlinx, Jackson reject null for `status` (Probe 16).

12. Duplicate keys: last occurrence wins for all four (Probe 20).

13. All accept `name` as null (Probes 1,5,11).

14. Moshi and kotlinx are stricter about types and unknown fields; Gson is most permissive; Jackson is strict but accepts some coercions like number to string.

15. kotlinx rejects documents with unknown fields, wrong types in arrays, and number where string expected.

16. Jackson rejects unknown fields and nulls for non-nullable fields, but accepts number-to-string coercion.

17. Gson converts numbers to strings for string fields and accepts unknown fields and nulls leniently.

18. Moshi rejects unknown fields and type mismatches strictly, but accepts number-to-string coercion like Gson.

19. Overall, disagreements arise on type coercion (number vs string), unknown fields, nullability of enums, and array element types.
