1. All accept fully well-formed documents with correct types (Probe 1).

2. All accept integer fields as strings if convertible (e.g., "id": "1") and decode correctly (Probe 2).

3. Gson, Moshi, Jackson accept "amount" as number and coerce to string; kotlinx.serialization rejects (Probe 3).

4. Gson, Moshi, Jackson accept "name" as number and coerce to string; kotlinx.serialization rejects (Probe 4).

5. Invalid enum "status" causes Moshi, kotlinx, Jackson to reject; Gson accepts with status=null (Probe 5).

6. All reject "tags" as string instead of array (Probe 6).

7. Gson, Moshi, Jackson accept numeric elements in "tags" array, coercing to strings; kotlinx rejects (Probe 7).

8. All accept nested "child" objects with correct types, including recursive one-level nesting (Probe 8).

9. All accept nested "child" with "id" as string convertible to int (Probe 9).

10. Gson, Moshi accept extra unknown fields at root; kotlinx, Jackson reject (Probe 10).

11. Gson accepts empty object for "child", filling missing fields with defaults/nulls; others reject missing required fields or nulls (Probe 11).

12. All accept "child": null (Probe 12).

13. Null "status" causes Moshi, kotlinx, Jackson to reject; Gson accepts with status=null (Probe 13).

14. Gson, Moshi, Jackson accept null elements inside "tags" array; kotlinx rejects (Probe 14).

15. Gson, Moshi, Jackson accept mixed-type elements in "tags" array, coercing non-strings to strings; kotlinx rejects (Probe 15).
